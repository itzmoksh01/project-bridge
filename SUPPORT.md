# Support

Thanks for using Project Bridge. This project is maintained in the open, and clear, reproducible reports are the most useful way to improve it.

## Choose the right channel

- **Something is broken:** open a [bug report](https://github.com/itzmoksh01/project-bridge/issues/new?template=bug_report.yml).
- **You have an idea:** open a [feature request](https://github.com/itzmoksh01/project-bridge/issues/new?template=feature_request.yml).
- **You want to contribute:** read [CONTRIBUTING.md](CONTRIBUTING.md) before opening a pull request.
- **You suspect a security vulnerability:** follow [SECURITY.md](SECURITY.md). Do not publish sensitive details in a public issue.

## What to include

For a bug or compatibility report, include as many of these as are safe to share:

1. Project Bridge version or commit.
2. Coding agent, exact version, operating system, and installation scope.
3. The shortest reproduction steps using a disposable or sanitized repository.
4. Expected behavior and actual behavior.
5. Relevant redacted output and which checks you ran.

## Protect private information

Never attach API keys, tokens, passwords, .env contents, private source code, customer information, personal data, or unredacted logs. Replace sensitive values with placeholders before posting.

## Response expectations

Project Bridge is a community project, not a paid support service. There is no guaranteed response time or service-level agreement. Issues may be prioritized by reproducibility, safety impact, scope, and maintainer availability.
